# BRAIN-N064 — Four-Bot Consortium Architecture Research

## Decision

A separate project/repository for the collaboration of four AI bots is architecturally justified, but it must be a **coordination substrate**, not a second Brain and not a second Forensic FSM.

## Evidence recovered

Current repository history shows:

- Bot-1 governance/state and worker-orchestration work.
- Bot-2 Quant-side admission/audit work and Bot-1 → Bot-2 handoff.
- Bot-3 forensic admission doctrine.
- a backup branch explicitly named `backup/bot1-bot2-bot3-bot4-20260821`.
- a feature branch named `feat/multi-bot-deliberation-governance`.

The exact canonical Bot-4 role is still not proven by the durable artifacts inspected in this action. Therefore Bot-4 remains UNKNOWN and denied by default.

## Architectural finding

The safest structure is:

```text
PROJECT_BRAIN_AI
  = canonical governance / state / admission / promotion / deny

FOUR-BOT CONSORTIUM
  = orchestration / delegation / bounded deliberation / task leases / scoped memory / receipts

DATA + QUANT
  = source truth and deterministic calculation
```

The consortium must use structured handoff envelopes and external durable state. Workers may submit results but may not rewrite canonical Brain state.

## Render constraint

The four-bot layer must not place four heavy resident agents in one Render Free 512 MB process. Use bounded invocations, compact handoffs, externalized large artifacts, bounded fan-out, timeouts and no unrestricted recursion.
